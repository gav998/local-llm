# Self-hosted portable offline RAGFlow + PaddleOCR / PP-StructureV3 + GGUF embeddings и LLM

`local-llm` — готовая полностью локальная RAG-система для поиска и ответов по
своим документам. Она распознаёт сканированные PDF и изображения,
восстанавливает текст и таблицы через PaddleOCR / PP-StructureV3, строит
локальные embeddings, индексирует документы и позволяет задавать вопросы
локальной LLM с переходом к цитатам и страницам первоисточника.

Сборка предназначена для закрытых и изолированных компьютеров. После
подготовки она работает без интернета, переносится вместе с данными на внешнем
диске и не требует Docker, WSL, прав администратора, Windows Services,
изменения реестра или системного `PATH`.

Внутри уже согласованы RAGFlow, OCR, локальная LLM, векторный и полнотекстовый
поиск, объектное хранилище и базы данных. Папку с договорами, инструкциями,
архивными сканами, отчётами и таблицами можно превратить в приватную базу
знаний: искать не только точную фразу, но и смысл, сопоставлять сведения из
разных файлов, получать ответы со ссылками на источники и строить простые
RAGFlow Agents и ingestion pipelines.

Сборка проверяется для Windows 11 x64 со следующим оборудованием:

- Intel Core i3-8350K;
- 32 ГБ RAM;
- две NVIDIA GTX 1080 по 8 ГБ.

Две видеокарты по 8 ГБ не считаются одной картой с 16 ГБ. Поэтому предусмотрены
отдельные режимы распознавания документов и общения с LLM: launcher сам
останавливает конфликтующие процессы и освобождает видеопамять при
переключении.

## Что вы получите

- приватный self-hosted RAGFlow, доступный только на текущем компьютере;
- OCR русских, украинских, белорусских и английских документов;
- распознавание сканов, структуры страниц и таблиц через PP-StructureV3;
- гибридный поиск по смыслу, ключевым словам и точным обозначениям;
- локальные ответы по одному или нескольким наборам документов;
- цитаты, имя исходного файла и переход к найденному месту в PDF;
- пакетную очередь разбора больших коллекций документов;
- RAGFlow Agents и настраиваемые pipelines для извлечения метаданных, резюме,
  ключевых слов и вопросов;
- все программы, модели, документы, индексы, логи, кэши и временные файлы
  внутри одной переносимой папки.

## Как теперь устроена сборка

Runtime разделён на восемь независимых portable-модулей:

| Модуль | Версия / назначение |
|---|---|
| `mysql` | MySQL 8.0.40, пользователи и настройки RAGFlow |
| `elasticsearch` | Elasticsearch 8.11.3, полнотекстовый и векторный индекс |
| `silo` | S3-compatible хранилище загруженных файлов |
| `valkey` | очередь заданий и кэш |
| `llama-cpp` | llama.cpp b10786 Vulkan, embeddings и chat LLM |
| `paddleocr` | PaddleOCR / PP-StructureV3, strict GPU без скрытого CPU fallback |
| `ragflow` | RAGFlow 0.27.1 API и task executor |
| `web` | RAGFlow UI и локальный Caddy |

Каждый модуль собирается отдельно в свой `.7z`, но обычная работа по-прежнему
выполняется одной командой `LOCAL-LLM.bat`. Разделение позволяет пересобрать
или заменить один компонент, не перепаковывая весь многогигабайтный комплект.

## Быстрый старт

Подготовка выполняется один раз на Windows-компьютере с интернетом. После неё
готовые архивы можно перенести на компьютер без интернета.

### 1. Скачайте проект на компьютер с интернетом

Откройте страницу [Releases](https://github.com/gav998/local-llm/releases),
выберите последний релиз, скачайте **Source code (zip)** и распакуйте архив.

Если Git уже установлен:

```bat
git clone https://github.com/gav998/local-llm.git
cd local-llm
```

Для online-сборки рекомендуется короткий путь на NTFS- или exFAT-диске,
например:

```text
X:\local_llm
```

В пути не должно быть символов `! % & ^ < > |`. Исходные установочные архивы
лежат в общем корневом `_src`, а wheelhouse, online-cache и прочие рабочие
кэши остаются в `modules\<имя>\_src`. Ничего не пишется на системный диск.

### 2. Соберите восемь модулей

Запустите двойным щелчком:

```text
1.PREPARE-ONLINE.bat
```

Выберите первый модуль. Когда исходного файла не хватает, сценарий покажет:

1. точное имя файла;
2. адрес для скачивания;
3. точный путь, куда положить файл, обычно `X:\local_llm\_src\`.

Скачайте файл браузером, не переименовывайте и не распаковывайте его вручную,
положите по указанному пути и вернитесь в окно сценария. После успешной сборки
снова откройте меню и последовательно соберите все восемь модулей.

Готовые архивы появляются в общем каталоге:

```text
X:\local_llm\prepared\
```

Повторять уже успешно собранный модуль не нужно. `CHECK-SOURCES.bat` только
проверяет наличие исходных загрузок и ничего не собирает. Полная подготовка
RAGFlow и OCR может занять около часа или больше в зависимости от интернета,
процессора и диска. При повторном запуске модуль использует уже скачанные
данные из своего `_src`; переносить или загружать их заново не требуется.

### 3. Соберите общую оболочку

Когда в `prepared` появились все восемь `.7z`, запустите:

```text
PREPARE-STACK.bat
```

Сценарий проверит наличие модульных архивов и создаст:

```text
prepared\local-llm-stack-2026.09.16.zip
```

Итоговый переносимый комплект состоит из девяти файлов: восьми модульных
`.7z` и одного `local-llm-stack-*.zip`.

### 4. Скачайте две GGUF-модели

GGUF не включаются в архивы: уже квантованные модели почти не сжимаются и
переносятся отдельно.

| Назначение | Рекомендуемый файл | Размер |
|---|---|---:|
| Поиск по смыслу и индексация | [Qwen3-Embedding-8B-Q4_K_M.gguf](https://huggingface.co/Qwen/Qwen3-Embedding-8B-GGUF/blob/main/Qwen3-Embedding-8B-Q4_K_M.gguf) | около 4,7 ГБ |
| Ответы на русском языке | [Vikhr-Nemo-12B-Instruct-R-21-09-24 Q4_K_M](https://huggingface.co/Content-AI/Vikhr-Nemo-12B-Instruct-R-21-09-24-Q4_K_M-GGUF/tree/main) | около 7,5 ГБ |

Файл Vikhr в источнике имеет длинное имя. После скачивания переименуйте его в:

```text
Vikhr-Nemo-12B-Q4_K_M.gguf
```

### 5. Перенесите и распакуйте комплект без интернета

На внешний HDD/SSD целевого компьютера скопируйте из `prepared`:

- `local-llm-stack-2026.09.16.zip`;
- все восемь файлов `local-llm-<module>-<version>.7z`;
- две GGUF-модели.

Создайте отдельную папку установки, например `G:\ragflow`. Распакуйте в неё
только `local-llm-stack-2026.09.16.zip`. Модульные `.7z` оставьте рядом с
распакованными `LOCAL-LLM.bat` и `EXTRACT-MODULES.bat`, затем запустите:

```text
EXTRACT-MODULES.bat
```

Сценарий использует вложенный `7za.exe` и сразу распаковывает все модульные
архивы. Отдельного тестирования архивов и SHA-проверок нет. Не распаковывайте
модульные архивы вручную старой версией 7-Zip.

Offline-путь может содержать пробелы и кириллицу, но не должен содержать
символы `! % & ^ < > |`.

### 6. Установите runtime

Откройте `cmd.exe` в папке установки и выполните:

```bat
LOCAL-LLM.bat install
```

Установка не обращается в интернет и ничего не устанавливает в Windows. Она
по очереди настроит восемь модулей, создаст локальные пароли и базы,
а также выполнит настоящий OCR-тест на NVIDIA GPU без скрытого перехода на
CPU. На медленном HDD это может занять заметное время.

Нужны только заранее установленные администратором NVIDIA driver и Vulkan
runtime. Сам проект драйверы не устанавливает и системные настройки не меняет.

После успешной установки скопируйте GGUF точно сюда:

```text
<папка local-llm>\
  modules\
    llama-cpp\
      models\
        embed\
          Qwen3-Embedding-8B-Q4_K_M.gguf
        llm\
          Vikhr-Nemo-12B-Q4_K_M.gguf
```

Если файлы имеют другие имена, при полностью остановленном стеке исправьте
`embedding_model` и `chat_model` в
`modules\llama-cpp\config\runtime\settings.json`.

### 7. Первый запуск

Проверьте нумерацию Vulkan-устройств:

```bat
LOCAL-LLM.bat devices
```

На проверенной конфигурации OCR использует первую GTX 1080, embedding в
профилях chat и ingestion запускается на той же Vulkan-карте через
`embedding_gpu_chat`, а chat LLM распределяется между картами. Если номера
устройств отличаются, сначала выполните `LOCAL-LLM.bat stop`, затем исправьте
`embedding_gpu_chat`, `chat_main_gpu` и `chat_tensor_split` в
`modules\llama-cpp\config\runtime\settings.json`, а для OCR отдельно
исправьте `gpu_index` в `modules\paddleocr\state\secrets.json`.

Для первоначальной настройки моделей запустите:

```bat
LOCAL-LLM.bat start chat
```

Когда появится `chat profile ready`, откройте:

```text
http://127.0.0.1:9388
```

Адрес доступен только на текущем компьютере. Интернет для работы не нужен.

> `LOCAL-LLM.bat` без аргументов теперь показывает справку по командам. Это
> нормально: интерактивное меню осталось у online-сборщика
> `1.PREPARE-ONLINE.bat`, а установленный стек управляется командами ниже.

## Первый вход и учётная запись

Готовой универсальной учётной записи и стандартного пароля нет. На странице
входа нажмите **Sign up / Регистрация** и создайте свою учётную запись: имя,
адрес в формате электронной почты и пароль. Письмо для подтверждения не
отправляется; адрес используется как логин и должен только иметь правильный
формат, например `user@local.test`.

Учётная запись, настройки и документы хранятся только в локальных модулях.
Можно создать несколько пользователей, но одна portable-установка рассчитана
на последовательную работу. Не запускайте одну папку одновременно из
нескольких Windows-сеансов. Данные разных пользователей не становятся общими
автоматически — для совместного доступа используйте механизмы Team/Share в
RAGFlow.

## Настройка моделей в RAGFlow

Launcher передаёт RAGFlow локальные chat- и embedding-модели. Обычно они
появляются автоматически. Откройте меню пользователя справа сверху → **Model
providers** и проверьте:

| Тип | Model name | Base URL | API key |
|---|---|---|---|
| Chat | `Vikhr-Nemo-12B-Q4_K_M` | `http://127.0.0.1:6381/v1` | `local-no-auth` |
| Embedding | `Qwen3-Embedding-8B-Q4_K_M` | `http://127.0.0.1:6380/v1` | `local-no-auth` |

Оба относятся к provider **OpenAI-API-Compatible**. В **System Model Settings
/ Set default models** выберите Vikhr как default chat model, а
Qwen3-Embedding — как default embedding model.

Если автоматические записи не появились, создайте в
**OpenAI-API-Compatible** две отдельные instances с адресами из таблицы:
модель типа **Chat** и модель типа **Embedding**. Проверка chat-модели проходит
только в профиле `start chat`; embedding работает в `chat` и `ingestion`.

### Подключение локального PP-StructureV3

Остановите chat-профиль и запустите ingestion:

```bat
LOCAL-LLM.bat start ingestion
```

Launcher сам остановит Vikhr, освободит видеопамять и запустит OCR, embeddings
и обработчик очереди. В **Model providers** найдите provider **PaddleOCR** и
создайте instance:

| Поле | Значение |
|---|---|
| Instance name | `Local PP-StructureV3` |
| PaddleOCR API URL | `http://127.0.0.1:9399` |
| PaddleOCR Algorithm | `PP-StructureV3` |
| Access token | значение `token` из `modules\paddleocr\state\secrets.json` |

Скопируйте только значение поля `token`, без кавычек. Не публикуйте этот файл:
он содержит локальный секрет OCR. Добавьте или включите OCR-модель
**PP-StructureV3**, выполните проверку соединения и при необходимости выберите
её как default OCR model.

## Типовой сценарий: большая папка документов

### 1. Создайте базу знаний

В RAGFlow база знаний называется **Dataset**.

1. Откройте **Dataset → Create dataset**.
2. Дайте понятное имя, например `Договоры 2018–2026`.
3. Выберите embedding model `Qwen3-Embedding-8B-Q4_K_M`.
4. Выберите **Parse type: Built-in** и метод **General**.
5. Укажите **Language: Russian**.
6. В **PDF parser / Layout recognizer** выберите созданный
   `PaddleOCR → PP-StructureV3`.
7. Для первого запуска оставьте chunk size `512`, delimiter `\n`, overlap
   `10%`, auto-keywords `0`, auto-questions `0`.
8. Сохраните Dataset.

Отдельно настраивать Elasticsearch, MySQL или хранилище не нужно. Раздел
**File** в RAGFlow — внутреннее файловое хранилище, а не произвольный доступ к
папкам Windows.

### 2. Загрузите и обработайте файлы

Убедитесь, что работает профиль `start ingestion`. В Dataset откройте **Files
→ Add file → Upload file**. Можно выбрать несколько файлов или вкладку
**Folder** для загрузки папки.

После загрузки:

1. отметьте нужные документы;
2. нажмите **Run / Parse**;
3. оставьте профиль ingestion запущенным до окончания обработки.

OCR, выделение таблиц, разбиение на chunks, вычисление embeddings и запись в
поисковый индекс выполняются автоматически как одна задача. Отдельно запускать
embeddings не требуется.

### 3. Следите за прогрессом

На странице **Dataset → Files** видны статус, процент обработки и число
chunks:

- `Waiting / Pending` — документ стоит в очереди;
- `Running` — идёт OCR, разбор или индексация;
- `Completed` — документ готов к поиску;
- `Failed` — откройте журнал и посмотрите причину;
- `Chunks = 0` после завершения — полезный текст не был извлечён.

Вкладка **Logs** показывает историю конкретных заданий. Команда
`LOCAL-LLM.bat status` показывает состояние программ, а не процент обработки
документов. Полные сервисные логи находятся в `modules\<name>\logs`, журнал
общей оболочки — в `stack\logs\control.log`.

До загрузки тысяч файлов проверьте 3–5 характерных документов: обычный PDF,
плохой скан и страницу со сложной таблицей. Нажмите имя готового документа,
чтобы увидеть chunks и соответствующие места исходного PDF.

### 4. Переделайте плохой старый OCR

Если в PDF уже есть ошибочный текстовый слой, выберите для документа или всего
Dataset именно `PaddleOCR → PP-StructureV3`, затем снова нажмите **Run /
Parse** и подтвердите замену старых chunks.

RAGFlow повторно распознает страницы и построит новый внутренний индекс.
Исходный PDF останется неизменным: сборка не записывает исправленный текстовый
слой обратно в PDF и не создаёт новый searchable PDF.

### 5. Проверьте поиск до общения с LLM

Откройте **Retrieval testing** внутри Dataset и попробуйте:

- точный номер договора, детали или изделия;
- фамилию и дату;
- смысловой вопрос другими словами;
- редкую фразу из найденного PDF.

Начальные параметры: similarity threshold `0.2`, vector similarity weight
`0.3`, Top N `8`, rerank model не выбирать. Если нужный фрагмент не найден,
сначала проверьте его наличие в chunks, затем уменьшайте threshold. Если
нерелевантных результатов слишком много — повышайте threshold.

### 6. Задавайте вопросы по документам

После индексации переключитесь на chat:

```bat
LOCAL-LLM.bat start chat
```

В RAGFlow:

1. откройте **Chat → Create chat**;
2. выберите один или несколько готовых Dataset;
3. выберите `Vikhr-Nemo-12B-Q4_K_M`;
4. оставьте в system prompt переменную `{knowledge}`;
5. включите **Show citations** и при необходимости **Show chunk metadata**;
6. начните с настроек `0.2 / 0.3 / Top N 8`;
7. сохраните Chat и откройте диалог.

Пример system prompt:

```text
Отвечай на русском языке только по переданным фрагментам базы знаний.
Не придумывай отсутствующие факты. Для каждого существенного утверждения
указывай исходный документ и страницу. Если данных недостаточно, прямо скажи об этом.

Контекст базы знаний:
{knowledge}
```

Для обычных вопросов начинайте с режима thinking **None/Low**. Для сравнения
нескольких документов можно попробовать **Medium**, но он медленнее.

### 7. Найдите упоминания в других документах

Если в PDF найден важный номер, фамилия, формулировка или событие:

1. вставьте точное обозначение в **Retrieval testing**;
2. либо спросите Chat: `Найди все документы, где упоминается X. Для каждого
   укажи файл, страницу, точную цитату и объясни связь.`;
3. откройте citations и перейдите к исходным местам;
4. если результатов мало, снизьте threshold или увеличьте Top N.

Пример сложного запроса:

```text
Сопоставь все упоминания «A-17» в выбранных документах. Построй таблицу:
документ, страница, дата, связанный объект, краткий контекст. Не объединяй
разные сущности без прямого подтверждения в источниках.
```

## Agents и пакетная обработка

### Обработать 2000 PDF и сделать их доступными для поиска

Обычный chat-agent для этого не нужен. Используйте очередь Dataset или
**Ingestion Pipeline**:

1. запустите `LOCAL-LLM.bat start ingestion`;
2. создайте **Ingestion Pipeline**;
3. соберите цепочку `Parser → Chunker → Indexer`;
4. в Parser выберите локальный `PaddleOCR / PP-StructureV3`;
5. в Chunker задайте `512` tokens и `10%` overlap;
6. в Indexer выберите **Hybrid**;
7. сначала проверьте pipeline на одном типовом файле;
8. сохраните его и выберите в **Dataset → Configuration → Parse type:
   Pipeline**;
9. загрузите папку, выделите документы и нажмите **Run**.

Файлы становятся независимыми заданиями. OCR gateway обрабатывает
распознавание последовательно, чтобы не переполнить 8 ГБ VRAM; строгий порядок
имён файлов не гарантируется. Ошибки фильтруйте по статусу `Failed` и
перезапускайте только неудачные документы.

Для одинаковых полей — номера, даты, контрагента, итоговой суммы — добавьте
между Chunker и Indexer компонент **Transformer → Metadata** и опишите поля.

### Простой Agent для готовой базы знаний

После индексации переключитесь на `start chat` и создайте **Conversational
Agent**:

```text
Begin → Retrieval → Agent → Message
```

- **Retrieval**: query `sys.query`, нужный Dataset, threshold `0.2`, Top N `8`;
- **Agent**: Vikhr, режим Precise, citations включены;
- user prompt: вопрос и `Retrieval.formalized_content` через меню переменных
  `/`;
- **Message**: `Agent.content`.

Пример инструкции:

```text
По запросу пользователя найди сведения в переданном контексте. Верни краткий
ответ, затем список подтверждающих документов. Не используй сведения, которых
нет в результатах Retrieval, и не скрывай противоречия между документами.
```

### Ограничение: Excel/Word и папки Windows

Текущий релиз не предоставляет Agent доступ к произвольной файловой системе
Windows и не умеет автоматически сохранять результаты 2000 PDF как отдельные
`.xlsx` или `.docx`. RAGFlow File хранит оригиналы во внутреннем S3-compatible
хранилище; это не Проводник Windows. Code Execution Sandbox намеренно отключён.

Для сценария «пройти по папке, изменить файлы и записать Excel/Word обратно»
нужен отдельный доверенный export worker или MCP-инструмент с явно разрешёнными
папками, правилами имён, форматом, журналом и возобновлением после ошибки. Такой
компонент в текущий релиз не входит.

## Какой профиль когда запускать

| Команда | Что запускается | Когда использовать |
|---|---|---|
| `LOCAL-LLM.bat start core` | базы, хранилище, RAGFlow API и web | настройки и просмотр без OCR/LLM |
| `LOCAL-LLM.bat start ingestion` | core + OCR + embeddings + worker | загрузка, OCR, chunks и индексация |
| `LOCAL-LLM.bat start chat` | core + embeddings + Vikhr | поиск, Chat и Agents |
| `LOCAL-LLM.bat status` | состояние процессов | убедиться, что сервисы запущены |
| `LOCAL-LLM.bat verify` | целостность модулей и health | диагностика повреждений |
| `LOCAL-LLM.bat devices` | Vulkan-устройства llama.cpp | проверить нумерацию GPU |
| `LOCAL-LLM.bat stop` | корректная остановка всего стека | перед переносом или резервной копией |

Не запускайте внутренние EXE вручную. Переключайте профили через
`LOCAL-LLM.bat`: он сам останавливает конфликтующие процессы и ждёт готовности
сервисов.

## Перенос, данные и резервная копия

Вся установка находится рядом с `LOCAL-LLM.bat`:

```text
modules\llama-cpp\models\          GGUF-модели
modules\mysql\data\mysql\         пользователи и настройки RAGFlow
modules\elasticsearch\data\index\ поисковый и векторный индекс
modules\silo\data\                 загруженные оригиналы
modules\valkey\data\               очередь и кэш
modules\paddleocr\data\jobs\      внутренние OCR-задания
modules\<name>\config\runtime\    настройки модуля
modules\<name>\state\             локальные секреты и PID-записи
modules\<name>\logs\              подробные логи
stack\logs\control.log            общий журнал launcher
```

Чтобы перенести систему вместе с пользователями и документами:

1. выполните `LOCAL-LLM.bat stop`;
2. дождитесь завершения команды;
3. скопируйте всю папку целиком;
4. запустите `LOCAL-LLM.bat start ...` с нового места.

Повторная установка после смены буквы диска не нужна. Нельзя отключать диск или
копировать рабочие базы во время записи.

## Отдельная сборка и управление модулем

Опытный пользователь может собрать и проверить только один компонент через
`1.PREPARE-ONLINE.bat`, а после распаковки управлять им напрямую:

```bat
modules\mysql\MODULE.bat install
modules\mysql\MODULE.bat start
modules\mysql\MODULE.bat verify
modules\mysql\MODULE.bat stop
```

Обычной установке это не требуется. Контракты соединений находятся в
`modules\<name>\state\connection.json`; модули общаются только через локальные
`127.0.0.1` endpoints.

## Если что-то не работает

1. Выполните `LOCAL-LLM.bat status`.
2. Проверьте профиль: `ingestion` нужен для OCR, `chat` — для ответов.
3. Убедитесь, что обе GGUF лежат под точными ожидаемыми именами.
4. У готового документа проверьте `Chunks > 0`.
5. Для ошибки файла откройте **Dataset → Logs**.
6. Посмотрите `stack\logs\control.log` и лог нужного сервиса в
   `modules\<name>\logs`.
7. Выполните `LOCAL-LLM.bat verify`.

Не удаляйте вручную базы, lock-файлы и staging, пока причина не установлена.
При обращении за помощью приложите команду, полный текст ошибки, результат
`status` и соответствующий лог. Файлы из `state`, содержащие пароли и токены,
прикладывать нельзя.
