# Self-hosted portable offline RAGFlow + PaddleOCR / PP-StructureV3 + GGUF embeddings и LLM

`local-llm` — готовая **полностью локальная RAG-система для поиска и ответов по своим документам**: она распознаёт сканированные PDF и изображения, восстанавливает текст и таблицы через PaddleOCR / PP-StructureV3, строит локальные embeddings, индексирует документы и позволяет задавать вопросы локальной LLM с переходом к цитатам и страницам первоисточника. Сборка создана для закрытых и изолированных компьютеров: после подготовки она работает без интернета, переносится вместе с данными на внешнем диске и не требует Docker, WSL, прав администратора, установки Windows Services или изменения системного `PATH`.

Внутри уже согласованы RAGFlow, OCR, локальная LLM, векторный и полнотекстовый поиск, объектное хранилище и базы данных. Это позволяет превратить папку с договорами, инструкциями, архивными сканами, отчётами и таблицами в приватную базу знаний: искать не только точную фразу, но и смысл, сопоставлять сведения из разных файлов, получать ответы со ссылками на источники и строить простые RAGFlow Agents и ingestion pipelines.

Сборка проверена на Windows 11 x64 со следующим оборудованием:

- Intel Core i3-8350K;
- 32 ГБ RAM;
- две NVIDIA GTX 1080 по 8 ГБ.

Две видеокарты по 8 ГБ не считаются одной картой с 16 ГБ. Поэтому предусмотрены отдельные режимы для распознавания документов и для общения с LLM: launcher сам освобождает нужную видеопамять при переключении.

## Что вы получите

- приватный self-hosted RAGFlow, доступный только на текущем компьютере;
- OCR русских, украинских, белорусских и английских документов;
- распознавание сканов, структуры страниц и таблиц через PP-StructureV3;
- гибридный поиск: по смыслу, ключевым словам и точным обозначениям;
- локальные ответы по одному или нескольким наборам документов;
- цитаты, имя исходного файла и переход к найденному месту в PDF;
- пакетную очередь разбора больших коллекций документов;
- RAGFlow Agents и настраиваемые pipelines для извлечения метаданных, резюме, ключевых слов и вопросов;
- все программы, модели, документы, индексы, логи, кэши и временные файлы внутри одной переносимой папки.

## Быстрый старт

Подготовка выполняется один раз на Windows-компьютере с интернетом. После неё готовую папку можно перенести на компьютер без интернета.

### 1. Скачайте проект на компьютер с интернетом

Самый простой способ — открыть страницу [Releases](https://github.com/gav998/local-llm/releases), выбрать последний релиз, скачать **Source code (zip)** и распаковать архив.

Если Git уже установлен, можно выполнить:

```bat
git clone https://github.com/gav998/local-llm.git
cd local-llm
```

Для online-сборки используйте короткий путь на NTFS- или exFAT-диске, например:

```text
X:\local_llm
```

В пути online-сборки не должно быть пробелов, кириллицы и символов `! # % & ( ) ; ^ < > |`.

### 2. Соберите переносимый комплект

Запустите двойным щелчком:

```text
1.PREPARE-ONLINE.bat
```

Сценарий последовательно проверит необходимые исходники и сторонние программы. Когда файла не хватает, он покажет:

1. точное имя файла;
2. адрес для скачивания;
3. точный путь, куда положить скачанный файл, обычно `X:\local_llm\_src\`.

Скачайте файл браузером, **не переименовывайте и не распаковывайте его вручную**, положите по указанному пути и вернитесь в окно сценария. Нажмите любую клавишу — подготовка продолжится. Так будут собраны все зависимости и локальные OCR-модели.

Полная сборка обычно занимает около часа, но время зависит от интернета, процессора и диска. Окно можно оставить работать: завершённые этапы сохраняются, и после устранимой ошибки сценарий можно запустить повторно.

Готовый переносимый комплект появится здесь:

```text
X:\local_llm\_src\prepared\
```

Успешный результат содержит `LOCAL-LLM.bat`, `prepared.ok`, `7zr.exe` и девять архивов `.7z`.

### 3. Скачайте две GGUF-модели

GGUF не включаются в архивы сборки: уже квантованные модели почти не сжимаются и переносятся отдельно.

| Назначение | Рекомендуемый файл | Размер |
|---|---|---:|
| Поиск по смыслу и индексация | [Qwen3-Embedding-8B-Q4_K_M.gguf](https://huggingface.co/Qwen/Qwen3-Embedding-8B-GGUF/blob/main/Qwen3-Embedding-8B-Q4_K_M.gguf) | около 4,7 ГБ |
| Ответы на русском языке | [Vikhr-Nemo-12B-Instruct-R-21-09-24 Q4_K_M](https://huggingface.co/Content-AI/Vikhr-Nemo-12B-Instruct-R-21-09-24-Q4_K_M-GGUF/tree/main) | около 7,5 ГБ |

Файл Vikhr в источнике имеет длинное имя. После скачивания переименуйте его в:

```text
Vikhr-Nemo-12B-Q4_K_M.gguf
```

### 4. Перенесите комплект на компьютер без интернета

Скопируйте **всю папку** `_src\prepared` на внешний HDD/SSD целевого компьютера. Её можно переименовать, например в `local-llm`. Внутри новой папки `LOCAL-LLM.bat` должен лежать рядом с девятью архивами `.7z`.

Отдельно перенесите два скачанных GGUF-файла. Пока их можно положить рядом с папкой — нужные каталоги появятся после установки.

Offline-путь может содержать пробелы и кириллицу, но не должен содержать символы `! % & ^ < > |`.

### 5. Установите runtime без интернета

На offline-компьютере откройте перенесённую папку и запустите:

```text
LOCAL-LLM.bat
```

Выберите пункт:

```text
1. Install / revalidate installation
```

Установка не обращается в интернет и ничего не устанавливает в Windows. Она распакует runtime в подпапку `app`, создаст локальные пароли и базы, проверит целостность файлов и обязательно выполнит настоящий OCR-тест на NVIDIA GPU без скрытого перехода на CPU. На медленном HDD это может занять заметное время.

Нужны заранее установленные администратором NVIDIA driver и Vulkan runtime. Сам проект драйверы не устанавливает и системные настройки не меняет.

После сообщения `Offline installation finalized` скопируйте GGUF точно сюда:

```text
<папка local-llm>\
  app\
    models\
      embed\
        Qwen3-Embedding-8B-Q4_K_M.gguf
      llm\
        Vikhr-Nemo-12B-Q4_K_M.gguf
```

Если вы оставили другие имена файлов, выберите пункт `8. Edit configuration and model paths` и укажите их в секции `[models]`.

### 6. Первый запуск

Сначала можно выбрать пункт `9. List llama.cpp Vulkan devices`. На проверенной конфигурации настройки рассчитаны на OCR на первой GTX 1080 и embeddings на второй. Если номера карт отличаются, остановите стек пунктом `6`, затем исправьте номера через пункт `8`.

Для первоначальной настройки моделей выберите:

```text
4. Start chat
```

Когда появится сообщение `Profile 'chat' is ready`, откройте в браузере:

```text
http://127.0.0.1:9388
```

Адрес доступен только на этом компьютере. Интернет для работы не нужен.

## Первый вход и учётная запись

Готовой универсальной учётной записи и стандартного пароля нет. На странице входа нажмите **Sign up / Регистрация** и создайте свою учётную запись: имя, адрес в формате электронной почты и пароль. Письмо для подтверждения не отправляется; адрес используется как логин и должен только иметь правильный формат, например `user@local.test`.

Учётная запись, её настройки и документы хранятся только в локальной MySQL внутри `app\data`. После регистрации пользуйтесь обычным **Sign in**.

Можно создать несколько пользователей, но эта portable-установка рассчитана на последовательную работу. Не запускайте одну папку одновременно из нескольких Windows-сеансов. Данные разных пользователей не становятся общими автоматически — для совместного доступа используйте механизмы Team/Share в RAGFlow.

## Настройка моделей в RAGFlow

Для каждой новой учётной записи launcher передаёт RAGFlow локальные chat- и embedding-модели. Обычно они появляются автоматически. Откройте меню пользователя справа сверху → **Model providers** и проверьте:

| Тип | Model name | Base URL | API key |
|---|---|---|---|
| Chat | `Vikhr-Nemo-12B-Q4_K_M` | `http://127.0.0.1:6381/v1` | `local-no-auth` |
| Embedding | `Qwen3-Embedding-8B-Q4_K_M` | `http://127.0.0.1:6380/v1` | `local-no-auth` |

Оба относятся к provider **OpenAI-API-Compatible**. В **System Model Settings / Set default models** выберите Vikhr как default chat model, а Qwen3-Embedding — как default embedding model.

Если автоматические записи не появились, создайте в **OpenAI-API-Compatible** две отдельные instances с адресами из таблицы, добавьте в первую модель типа **Chat**, во вторую модель типа **Embedding**, затем назначьте их моделями по умолчанию. Проверка chat-модели проходит только в профиле `Start chat`; embedding работает и в `chat`, и в `ingestion`.

### Подключение локального PP-StructureV3

Вернитесь к `LOCAL-LLM.bat` и выберите:

```text
3. Start ingestion
```

Launcher сам остановит Vikhr, освободит видеопамять и запустит OCR, embeddings и обработчик очереди. Снова откройте **Model providers**, найдите provider **PaddleOCR** и создайте instance со значениями:

| Поле | Значение |
|---|---|
| Instance name | `Local PP-StructureV3` |
| PaddleOCR API URL | `http://127.0.0.1:9399` |
| PaddleOCR Algorithm | `PP-StructureV3` |
| Access token | значение `ocr_token` из `app\config\runtime\secrets.json` |

Откройте `secrets.json` Блокнотом и скопируйте только значение после `"ocr_token":`. Кавычки копировать не нужно. Не публикуйте этот файл: в нём находятся также пароли локальных сервисов.

В instance добавьте/включите OCR-модель **PP-StructureV3** и выполните проверку соединения. Если интерфейс предлагает назначить default OCR model, выберите её.

## Типовой сценарий: разобраться в большой папке документов

### 1. Создайте базу знаний

В RAGFlow база знаний называется **Dataset**.

1. Откройте **Dataset → Create dataset**.
2. Дайте понятное имя, например `Договоры 2018–2026`.
3. Выберите embedding model `Qwen3-Embedding-8B-Q4_K_M`.
4. Выберите **Parse type: Built-in** и метод **General**.
5. В конфигурации укажите **Language: Russian**.
6. В поле **PDF parser / Layout recognizer** выберите созданный `PaddleOCR → PP-StructureV3`.
7. Для первого запуска оставьте простые настройки: chunk size `512`, delimiter `\n`, overlap `10%`, auto-keywords `0`, auto-questions `0`.
8. Сохраните Dataset.

Если после выбора PaddleOCR интерфейс дополнительно показывает URL, token и algorithm, используйте те же значения из предыдущего раздела.

Отдельно настраивать Elasticsearch, MySQL или хранилище не нужно. Они создаются автоматически и находятся внутри `app\data`. Раздел **File** в RAGFlow — это внутреннее файловое хранилище RAGFlow, а не произвольный доступ к папкам Windows.

### 2. Загрузите и обработайте файлы

Убедитесь, что работает профиль `Start ingestion`.

В Dataset откройте **Files → Add file → Upload file**. Можно выбрать несколько файлов или вкладку **Folder** для загрузки папки. Для повторного использования одних файлов в разных Dataset удобнее сначала загрузить их в раздел **File**, а затем связать с нужными Dataset.

После загрузки:

1. отметьте нужные документы;
2. нажмите **Run / Parse**;
3. оставьте профиль ingestion запущенным до окончания обработки.

OCR, выделение таблиц, разбиение на chunks, вычисление embeddings и запись в поисковый индекс выполняются автоматически как одна задача. Отдельно запускать embeddings не требуется.

### 3. Следите за прогрессом

На странице **Dataset → Files** у каждого документа видны статус, процент обработки и число chunks:

- `Waiting / Pending` — документ стоит в очереди;
- `Running` — идёт OCR, разбор или индексация;
- `Completed` — документ готов к поиску;
- `Failed` — откройте журнал и посмотрите причину;
- `Chunks = 0` после завершения — полезный текст не был извлечён, результат нужно проверить.

Вкладка **Logs** показывает историю и подробности каждой задачи. Пункт `5. Status` в `LOCAL-LLM.bat` показывает состояние программ, а не процент документов. Живой текст в отдельном консольном окне и полные файлы в `app\logs` нужны прежде всего для диагностики.

Нажмите имя готового документа, чтобы увидеть распознанные chunks. При выборе фрагмента RAGFlow показывает соответствующее место исходного PDF. До загрузки тысяч файлов разумно проверить 3–5 характерных документов: обычный PDF, плохой скан и страницу со сложной таблицей.

### 4. Как переделать плохой старый OCR

Если в PDF уже есть ошибочный текстовый слой, выберите для документа или всего Dataset именно `PaddleOCR → PP-StructureV3`, затем выделите документ и снова нажмите **Run / Parse**. В диалоге подтвердите замену старых chunks.

RAGFlow повторно распознает страницы и построит новый внутренний индекс. Исходный PDF останется неизменным: сборка не записывает исправленный текстовый слой обратно в PDF и не создаёт новый searchable PDF.

### 5. Проверьте поиск до общения с LLM

Откройте **Retrieval testing** внутри Dataset и попробуйте:

- точный номер договора, детали или изделия;
- фамилию и дату;
- смысловой вопрос другими словами;
- редкую фразу из найденного PDF.

Начальные параметры: similarity threshold `0.2`, vector similarity weight `0.3`, Top N `8`, rerank model не выбирать. Если нужный фрагмент не найден, сначала проверьте его наличие в chunks, затем уменьшайте threshold. Если нерелевантных результатов слишком много — повышайте threshold.

### 6. Задавайте вопросы по документам

После завершения обработки вернитесь в `LOCAL-LLM.bat` и выберите:

```text
4. Start chat
```

Launcher остановит OCR и worker, перенесёт embedding на другую GPU и запустит Vikhr.

В RAGFlow:

1. откройте **Chat → Create chat**;
2. выберите один или несколько готовых Dataset;
3. выберите модель `Vikhr-Nemo-12B-Q4_K_M`;
4. оставьте в system prompt переменную `{knowledge}`;
5. включите **Show citations** и при необходимости **Show chunk metadata**;
6. начните с retrieval-настроек `0.2 / 0.3 / Top N 8`;
7. сохраните Chat и откройте диалог.

Пример system prompt:

```text
Отвечай на русском языке только по переданным фрагментам базы знаний.
Не придумывай отсутствующие факты. Для каждого существенного утверждения
указывай исходный документ и страницу. Если данных недостаточно, прямо скажи об этом.

Контекст базы знаний:
{knowledge}
```

Для обычных вопросов начинайте с режима thinking **None/Low**. Для сравнения нескольких документов можно попробовать **Medium**, но он медленнее и делает больше обращений к локальной LLM.

### 7. Найдите упоминания в других документах

Если вы нашли в PDF важный номер, фамилию, формулировку или событие:

1. вставьте точное обозначение в **Retrieval testing**, чтобы увидеть все найденные chunks и их документы;
2. либо спросите Chat: `Найди все документы, где упоминается X. Для каждого укажи файл, страницу, точную цитату и объясни связь.`;
3. откройте citations под ответом и перейдите к исходным местам;
4. если результатов мало, снизьте similarity threshold или увеличьте Top N.

Для сложного сопоставления полезен запрос:

```text
Сопоставь все упоминания «A-17» в выбранных документах. Построй таблицу:
документ, страница, дата, связанный объект, краткий контекст. Не объединяй
разные сущности без прямого подтверждения в источниках.
```

## Типовой сценарий: Agents и пакетная обработка

Здесь важно различать две задачи.

### Обработать 2000 PDF и сделать их доступными для поиска

Для этого обычный chat-agent не нужен. Надёжнее использовать очередь Dataset или **Ingestion Pipeline**:

1. запустите профиль `Start ingestion`;
2. в **Agent → Create Agent** выберите тип **Ingestion Pipeline** или готовый шаблон;
3. соберите простую цепочку `Parser → Chunker → Indexer`;
4. в Parser для PDF выберите локальный `PaddleOCR / PP-StructureV3`;
5. в Chunker задайте `512` tokens и `10%` overlap;
6. в Indexer выберите **Hybrid**; локальный Qwen3 embedding будет взят из настроек Dataset автоматически;
7. нажмите **Run** и сначала проверьте pipeline на одном типовом файле;
8. сохраните pipeline и выберите его в **Dataset → Configuration → Parse type: Pipeline**;
9. загрузите папку, выделите документы и нажмите **Run**.

Файлы становятся независимыми заданиями очереди. OCR gateway обрабатывает распознавание последовательно, чтобы не переполнить 8 ГБ VRAM; строгий порядок имён файлов не гарантируется. Оставьте компьютер и профиль ingestion включёнными. Ход обработки смотрите в **Files** и **Logs**, ошибки фильтруйте по статусу `Failed` и перезапускайте только неудачные документы.

Если нужно извлечь из каждого документа одинаковые поля — например номер, дату, контрагента и итоговую сумму — добавьте между Chunker и Indexer компонент **Transformer → Metadata**, задайте поля и их описание. Результаты сохранятся как metadata и смогут использоваться для фильтрации и поиска.

### Простой Agent для работы с готовой базой знаний

После индексации переключитесь на `Start chat`, затем создайте **Conversational Agent** со схемой:

```text
Begin → Retrieval → Agent → Message
```

Настройте:

- в **Retrieval**: query `sys.query`, нужный Dataset, threshold `0.2`, Top N `8`;
- в **Agent**: модель Vikhr, режим Precise, citations включены;
- в user prompt Agent вставьте вопрос и `Retrieval.formalized_content` через меню переменных `/`;
- в **Message** выведите `Agent.content`.

Пример инструкции Agent:

```text
По запросу пользователя найди сведения в переданном контексте. Верни краткий
ответ, затем список подтверждающих документов. Не используй сведения, которых
нет в результатах Retrieval, и не скрывай противоречия между документами.
```

Сохраните Agent и проверьте его несколькими вопросами, для которых заранее известны правильные ответы.

### Ограничение: создание Excel/Word и доступ к папкам Windows

Текущий релиз **не предоставляет Agent доступ к произвольной файловой системе Windows** и не умеет автоматически сохранить результаты 2000 PDF как отдельные `.xlsx` или `.docx`. RAGFlow File хранит загруженные оригиналы во внутреннем S3-compatible хранилище; это не проводник Windows. Code Execution Sandbox в этой portable-сборке намеренно отключён (`SANDBOX_ENABLED=0`).

Поэтому сценарий «пройти по папке, изменить файлы и записать Excel/Word обратно» нельзя получить одной только текстовой инструкцией Agent. Для него нужен отдельный доверенный export worker или MCP-инструмент с явно разрешёнными входной и выходной папками, правилами имён, форматом таблицы, журналом и возобновлением после ошибки. Такой компонент в текущий релиз не входит. Уже сейчас можно пакетно OCR-обработать и проиндексировать 2000 файлов, извлечь metadata и работать с результатом внутри RAGFlow.

## Какой режим когда запускать

| Пункт меню | Что запускается | Когда использовать |
|---|---|---|
| `2. Start core` | базы, хранилище, RAGFlow и web | просмотр настроек и документов без OCR/LLM |
| `3. Start ingestion` | core + OCR + embeddings + worker | загрузка, повторный OCR, разбор, chunks и индексация |
| `4. Start chat` | core + embeddings + Vikhr | поиск, Chat и Agents по уже готовым документам |
| `5. Status` | проверка процессов и health | убедиться, что сервисы готовы |
| `6. Stop all` | корректная остановка всего стека | перед отключением диска, переносом или резервной копией |
| `7. Verify` | проверка файлов установки | диагностика повреждения runtime |
| `8. Edit configuration` | пути, порты, GPU и память | только при остановленном стеке |
| `9. List Vulkan devices` | список GPU llama.cpp | проверка нумерации видеокарт |

Не запускайте отдельные BAT или EXE из `app` вручную. Переключайте режимы через `LOCAL-LLM.bat`: он сам останавливает конфликтующие процессы и ждёт готовности нужных сервисов.

## Перенос, данные и резервная копия

Вся установка находится рядом с `LOCAL-LLM.bat`:

```text
app\models\                    GGUF-модели
app\data\mysql\               пользователи и настройки RAGFlow
app\data\elasticsearch\       поисковый и векторный индекс
app\data\silo\                загруженные оригиналы
app\data\valkey\              очередь и кэш
app\data\ocr-jobs\            внутренние OCR-задания
app\config\runtime\           настройки и секреты
app\logs\                      подробные логи
```

Чтобы перенести систему вместе с пользователями и документами:

1. выберите `6. Stop all` и дождитесь сообщения об остановке;
2. скопируйте всю папку целиком;
3. запустите `LOCAL-LLM.bat` с нового места.

Повторная установка после смены буквы диска не нужна. Нельзя отключать диск или копировать рабочие базы во время записи.

## Команды для опытных пользователей

```bat
LOCAL-LLM.bat install
LOCAL-LLM.bat start core
LOCAL-LLM.bat start ingestion
LOCAL-LLM.bat start chat
LOCAL-LLM.bat status
LOCAL-LLM.bat stop
LOCAL-LLM.bat verify
LOCAL-LLM.bat verify --gpu
LOCAL-LLM.bat config show
LOCAL-LLM.bat config edit
LOCAL-LLM.bat devices
```

Пользовательские настройки находятся в `app\config\runtime\local-llm.ini`. Перед их изменением обязательно выполните `stop`.

## Если что-то не работает

1. Выполните `LOCAL-LLM.bat status`.
2. Проверьте, что выбран правильный профиль: ingestion для OCR, chat для ответов.
3. Убедитесь, что у готового документа `Chunks > 0`.
4. Откройте **Dataset → Logs** для ошибки конкретного файла.
5. Посмотрите полный лог нужного сервиса в `app\logs`.
6. Не удаляйте вручную базы, lock-файлы и папки staging, пока не установлена причина ошибки.

При обращении за помощью приложите команду или пункт меню, полный текст ошибки, результат `status` и соответствующий лог. Файл `app\config\runtime\secrets.json` прикладывать нельзя.

## Состав сборки

| Компонент | Версия / профиль |
|---|---|
| RAGFlow | `0.27.1`, native Windows compatibility patch |
| PaddleOCR / PaddleX | `3.7.0` / `3.7.2` |
| PaddlePaddle | GPU `3.3.1`, CUDA 11.8, `sm_61` |
| OCR | PP-StructureV3: layout, East Slavic OCR и таблицы |
| Embeddings | `Qwen3-Embedding-8B-Q4_K_M.gguf` через llama.cpp |
| Chat LLM | `Vikhr-Nemo-12B Q4_K_M` через llama.cpp |
| llama.cpp | `b10786`, Windows Vulkan |
| Хранилище и поиск | MySQL 8.0.40, Elasticsearch 8.11.3, Silo, Valkey |
| Web | Caddy 2.11.4, только `127.0.0.1` |

Native Windows не является официальным deployment target RAGFlow, поэтому версии и совместимые исправления здесь строго закреплены. Подробности об изоляции, trust chain, GPU-профилях, OCR gateway и управлении процессами находятся в [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md).
