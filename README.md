# local_llm

Набор независимо запускаемых portable-папок для Windows 11 x64. Каждая серверная
папка содержит собственный launcher, runtime, зависимости, конфигурацию и данные;
корень репозитория не нужен ей во время работы. Ничего не устанавливается в
систему, не нужны права администратора, системный Python, Docker или PATH.

- `gost-gsm-mcp` — отдельный HTTP MCP на `127.0.0.1:8765`;
- `office-tools` — отдельный HTTP MCP для Word/Excel на `127.0.0.1:8766` и
  необязательный CLI;
- `llama`, `paddleocr`, `digitizer` — отдельные приложения со своими launchers;
- `vscode` — каталог для официального portable VS Code ZIP с готовым профилем,
  глобальными MCP и custom agents.

Чтобы работать агентом, запустите только нужные серверы отдельными окнами. Их не
запускает workspace и они не завершаются при закрытии VS Code.

## gost-gsm-mcp

Детерминированный HTTP MCP-помощник и два VS Code custom agents для поэтапной
сериализации больших OCR-таблиц ГСМ из HTML/Markdown в три нормализованные CSV.
Он считает строки и ячейки, ведёт batch-progress, сохраняет provenance и review
flags, поддерживает точечные overrides и не позволяет молча экспортировать
неоднозначные связи.

Запустите `gost-gsm-mcp\start.bat`, затем выберите `GSM GOST Orchestrator` и
передайте путь к OCR-документу. Первый запуск сам готовит portable Python внутри
модуля. Подробная инструкция: [`gost-gsm-mcp/README.md`](gost-gsm-mcp/README.md).

## vscode

Распакуйте официальный Windows x64 ZIP VS Code прямо в папку `vscode`, чтобы
получился `vscode\Code.exe`, и запускайте этот exe обычным способом. Уже
существующая `vscode\data` включает штатный Portable Mode: профиль, расширения и
временные файлы остаются рядом с редактором без launcher-скриптов. Профиль
содержит глобальные HTTP MCP-подключения и агентов, поэтому можно открыть любую
папку с документами — копировать `.github`, `.vscode` или инструкции в каждую
workspace не требуется. Подробности:
[`vscode/README.md`](vscode/README.md).

## llama

1. Положите GGUF-модели в `llama\models\llm` и `llama\models\embed`.
2. Запустите `llama\start.bat`.
3. Если `llama\llama-cpp\llama-server.exe` отсутствует, скрипт найдёт архив
   `llama\_src\llama-b10786-bin-win-vulkan-x64.zip` либо предложит скачать его.
4. Выберите LLM, затем размер контекста. Доступны профили 16K, 32K, 64K, 128K
   и точный числовой ввод от 4096 до 131072 токенов. Текущий статус всегда виден
   в верхней части меню.

Split GGUF не нужно предварительно объединять. Положите все части одной модели
рядом в соответствующую папку, сохранив стандартные имена
`имя-00001-of-000NN.gguf` ... `имя-000NN-of-000NN.gguf`. В меню весь набор
показывается как одна модель; launcher передаёт `llama-server` первую часть, а
остальные части `llama.cpp` загружает автоматически. Если хотя бы одной части
не хватает, набор не запускается и в меню выводится имя отсутствующего файла.

OpenAI-совместимые API по умолчанию:

- chat: `http://127.0.0.1:6381/v1`, ключ `local-llm`;
- embeddings: `http://127.0.0.1:6380/v1`, ключ `local-llm`.

Порты, ключ и GPU-настройки находятся в `llama\config.json`. При выходе из меню
все запущенные этим окном серверы останавливаются.

Для `Qwen2.5-7B-Instruct-Q4_K_M` на двух GTX 1080 по 8 ГБ профиль 128K — попытка
использовать полный заявленный контекст модели, когда обе карты свободны. Для
64K/128K скрипт автоматически:

- делит модель и KV-кэш поровну между GPU;
- использует Q8-кэш вместо F16, чтобы примерно вдвое сократить его память;
- включает Flash Attention;
- включает YaRN для Qwen2.5 7B Instruct, потому что GGUF имеет нативный контекст
  32K, а более длинный требует масштабирования RoPE.

128K заметно медленнее, чем 32K, и окончательный результат зависит от реальной
свободной VRAM и Vulkan-драйвера. Скрипт не уменьшает выбранный контекст скрытно:
при нехватке памяти сервер завершится, а причина останется в
`llama\logs\llm.error.log`. Тогда запустите 64K или 32K. Для повседневных коротких
задач 32K обычно быстрее и не использует статический YaRN.

### Локальный агент в VS Code

Для агента рекомендуется
[`Qwen2.5-7B-Instruct-Q4_K_M.gguf`](https://huggingface.co/bartowski/Qwen2.5-7B-Instruct-GGUF/blob/main/Qwen2.5-7B-Instruct-Q4_K_M.gguf).
Положите файл в `llama\models\llm`; имя менять не требуется. Стандартная
конфигурация уже включает `--jinja` и tool calling, а контекст выбирается при
каждом запуске, поэтому редактировать `config.json` не нужно.

1. Запустите `llama\start.bat`, выберите `[1] Start LLM`, нужную Qwen-модель и
   контекст. Для двух свободных карт можно начать со 128K; если сервер не
   поместится в VRAM, выберите 64K.
2. Скрипт дождётся сервера и проверит `/props`. Если GGUF не содержит шаблон,
   способный принимать tools, запуск завершится понятной ошибкой, а VS Code не
   получит ложный флаг `toolCalling`.
3. После успешного запуска скопируйте содержимое `llama\vscode-model.json` в
   `chatLanguageModels.json`. Для комплекта из этого репозитория это
   `vscode\data\user-data\User\chatLanguageModels.json`. Сгенерированный файл
   уже содержит фактический выбранный контекст и не требует ручной правки.
4. Перезагрузите окно VS Code, откройте нужную рабочую папку, выберите Session
   Target `Local`, режим `Agent` и модель из группы `Local llama.cpp`. Для первого
   знакомства оставьте подтверждение инструментов в режиме `Manual`.

Параметры соединения записываются в `llama\connection.json`, а готовая резервная
конфигурация модели — в `llama\vscode-model.json`. Оба файла создаются локально и
не попадают в Git. Скрипт не изменяет конфигурацию VS Code. Endpoint слушает
только `127.0.0.1` и использует локальный ключ `local-llm`.

Доступ агента к диску определяется открытой workspace и разрешениями VS Code, а
не параметром `vscode_tool_calling`. Этот параметр означает только, что модель
может формировать структурированные запросы инструментов. В portable VS Code
выберите `File` → `Add Folder to Workspace...` и добавьте любой нужный каталог с
документами. Можно добавить корень диска, но отдельные рабочие папки быстрее
индексируются и дают агенту меньше лишних прав. Сохраните multi-root workspace,
чтобы выбор не повторять при следующих запусках.

Обычные inline suggestions и семантический поиск VS Code через этот
OpenAI-compatible endpoint не работают. Для них требуются отдельные механизмы.

### Word и Excel

Запустите `office-tools\start.bat`. Агент `Local Document Worker` получает
структурированные инструменты `inspect_word`, `inspect_excel`,
`replace_word_text`, `set_excel_cells`, `create_word` и `create_excel` напрямую
по MCP. Он не должен просить пользователя вручную выполнять `office.bat`.

При первом старте автоматически скачивается собственный Python и устанавливаются
MCP SDK, `python-docx` и `openpyxl` внутрь `office-tools`; системный Python и права
администратора не нужны. CLI `office.bat` оставлен для ручной диагностики и не
является основным агентским интерфейсом. Запись по умолчанию не перезаписывает
оригинал и повторно открывает результат для проверки.

Формулы Excel сохраняются, но `openpyxl` их не вычисляет. Для пересчёта формул,
сложных диаграмм и ActiveX нужен установленный Excel/LibreOffice. Старые `.doc` и
`.xls` сначала нужно конвертировать.

## paddleocr

Запустите `paddleocr\start.bat` и выберите функциональный профиль. На первом
запуске скрипт сам скачает embedded Python, CUDA 11.8 wheel и только модели,
которые нужны выбранному профилю. Остальные модели лениво скачиваются при их
первом выборе. Всё сохраняется внутри `paddleocr`; установочные архивы после
успешной установки удаляются.

PDF или изображение (`PNG`, `JPEG`, `TIFF`, `BMP`) можно перетащить мышью прямо
на `paddleocr\start.bat`. Сначала откроется меню: выберите профиль, которым нужно
обработать документы. После его загрузки документы по очереди ставятся в
локальную OCR-очередь, а результат сохраняется рядом с оригиналом как
`<имя>.md`. Если в документе есть извлечённые изображения, они сохраняются в
соседнюю папку `<имя>_assets`, и Markdown уже содержит правильные относительные
ссылки. Можно одновременно перетащить несколько файлов — они будут обработаны
последовательно, после чего приложение останется в меню с запущенным профилем.
В строку `Select` также можно ввести абсолютный или относительный путь к PDF или
изображению, чтобы распознать его текущим профилем.

Доступные профили:

- быстрый текст — лёгкий `PP-OCRv6_tiny_det` и русское распознавание;
- точный текст — `PP-OCRv6_medium_det` без таблиц и прочих ветвей;
- текст + печати;
- текст + формулы;
- Digitizer — текст + печати + формулы;
- документы и автоматические таблицы;
- полный PP-StructureV3.

Одновременно на порту работает один профиль. При выборе другого текущий процесс
останавливается и память GPU освобождается до загрузки нового. Текущий профиль,
возможности и реально загруженные модели доступны в `/health`.

API слушает `http://127.0.0.1:9399`, ключ по умолчанию `local-ocr`:

```bat
curl.exe -H "Authorization: Bearer local-ocr" -F "file=@scan.png" http://127.0.0.1:9399/v1/ocr
```

Ответ: JSON с общим полем `text` и массивом `pages`. Асинхронный API
`/api/v2/ocr/jobs` также сохранён для digitizer. По умолчанию OCR выбирает GPU 1,
если видны две видеокарты, иначе GPU 0. Параметры находятся в
`paddleocr\config.json`; временно переопределить их можно так:

```bat
paddleocr\start.bat -Port 9399 -ApiKey local-ocr -Device auto -Profile digitizer
```

## digitizer

Сначала запустите PaddleOCR, при необходимости — chat-модель llama.cpp, затем
`digitizer\start.bat`. Embedded Python и зависимости установятся автоматически,
после чего откроется `http://127.0.0.1:9400`.

Без аргументов URL и ключи читаются из соседних папок `paddleocr` и `llama`.
Если папки находятся отдельно, укажите значения явно:

```bat
digitizer\start.bat -PaddleUrl http://127.0.0.1:9399 -PaddleKey local-ocr -LlamaUrl http://127.0.0.1:6381/v1 -LlamaKey local-llm
```

Llama используется только для выбранных пользователем операций исправления OCR;
Digitizer можно запускать без PaddleOCR и llama.cpp: ручная разметка и
редактирование PDF остаются доступны, а попытка OCR или ИИ-коррекции покажет
ошибку недоступного сервиса. Данные остаются в `digitizer\data` и рядом с
открытыми PDF.

Рабочий сценарий Digitizer: сначала выделите прямоугольник на PDF, затем в
правых колонках выберите существующий объект либо создайте типовой объект и
укажите его конечное поле. OCR-модель вручную не выбирается: поля используют
семантические режимы «текст», «печать», «формула» и их сочетания. Таблицы
размечаются собственной сеткой Digitizer, поэтому модель автоматического
восстановления таблиц для них не нужна. Заголовки, строки и значения групп можно
добавлять вручную; группы назначаются выбранным строкам. Поворот 0/90/180/270°
применяется только к фрагменту, отправляемому в OCR, и не меняет PDF.

Разметка хранится рядом с PDF в схеме 2. Файлы старой схемы 1 автоматически
переносятся при открытии; исходный PDF не изменяется.

Закрытие соответствующего `start.bat` или нажатие Enter в нём останавливает
запущенный из этого окна процесс.
