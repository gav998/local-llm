# Local Image Editor

Независимый portable API для локального редактирования фрагментов изображения по маске и
фотографии-референсу. Он использует `DreamShaper 8 Inpainting`,
`IP-Adapter FaceID Plus v2` и face embedding из InsightFace. Это отдельный процесс:
`llama.cpp` исполняет GGUF-языковые модели и не умеет запускать diffusion/IP-Adapter.

В отличие от обычного `IP-Adapter Plus Face`, FaceID фиксирует идентичность человека через
нормализованный ArcFace embedding. Перед генерацией редактор находит лицо на референсе,
выравнивает его и передаёт модели одновременно FaceID- и CLIP-признаки. На исходном
изображении автоматически вырезается квадрат вокруг белой области маски с запасом: лицо
увеличивается до рабочего разрешения 512×512, а готовый участок возвращается на прежнее
место. Пиксели вне маски сохраняются.

Расчёт сделан под Windows 11 x64 и GTX 1080 8 ГБ. Редактор автоматически обнаруживает все
видимые совместимые NVIDIA GPU и создаёт по одному независимому воркеру с моделью на каждую
карту. Общая FIFO-очередь отдаёт следующий слайд первой освободившейся GPU. На компьютере с
одной картой запросы выполняются последовательно; на компьютере без CUDA запуск завершается
ошибкой без скрытого CPU fallback. Две карты по 8 ГБ при этом не превращаются в одну карту на
16 ГБ: каждая обрабатывает отдельное изображение.

## Запуск

Запустите `start.bat`. Первый старт автоматически скачивает внутрь этой папки portable
Python 3.11, CUDA 11.8 build PyTorch, зависимости, DreamShaper, FaceID Plus v2, CLIP ViT-H
и InsightFace `buffalo_l`. Права администратора, системный Python, Docker, WSL и изменение
`PATH` не нужны. Для первого старта нужен интернет и около 10 ГБ свободного места; следующие
старты работают с локальным кэшем `models/`. После обновления прежнего редактора portable
runtime автоматически переустановит новые зависимости при первом запуске.

API после загрузки доступен по адресу `http://127.0.0.1:9410`. Состояние:

```bat
curl.exe http://127.0.0.1:9410/health
```

Редактирование (белая часть маски перерисовывается, чёрная сохраняется):

```bat
curl.exe -X POST http://127.0.0.1:9410/v1/images/edits ^
  -H "Authorization: Bearer local-image-editor" ^
  -F "image=@fragment.png" ^
  -F "mask=@mask.png" ^
  -F "reference_image=@Иванов.jpg" ^
  -F "steps=35" ^
  -F "seed=42" ^
  --output result.png
```

Пакет слайдов можно отправить одним запросом. Поля `images` и `masks` повторяются для каждого
слайда. Можно передать одну общую фотографию в `reference_images` либо столько фотографий,
сколько слайдов. Результат — ZIP с PNG-файлами и `manifest.json`; отдельная ошибка обработки
одного слайда записывается в manifest и не удаляет успешные результаты остальных:

```bat
curl.exe -X POST http://127.0.0.1:9410/v1/images/edits/batch ^
  -H "Authorization: Bearer local-image-editor" ^
  -F "images=@slide-01.png" -F "masks=@mask-01.png" ^
  -F "images=@slide-02.png" -F "masks=@mask-02.png" ^
  -F "reference_images=@Иванов.jpg" ^
  -F "seed=42" ^
  --output image-edits.zip
```

Если используется прежний одиночный endpoint, клиент также может отправлять несколько HTTP-
запросов параллельно: они попадут в ту же очередь и автоматически распределятся по картам.
Последовательная отправка одиночных запросов ускорения от второй GPU не даст.

Для `reference_image` лучше использовать чёткое фото одного человека анфас, без очков,
закрывающих глаза, и без других лиц. Если лиц несколько, берётся самое крупное; если лицо
не найдено, API возвращает HTTP 422 с понятным сообщением.

На каждой GPU одновременно выполняется не более одной генерации, поэтому пиковая VRAM одной
карты ограничена одним заданием. Diffusion работает с CPU-offload, а короткий анализ референса
— через InsightFace/ONNX Runtime на CPU, чтобы не конфликтовать с CUDA 11.8 и не отнимать VRAM
у GTX 1080. Для двух одновременных pipeline требуется больше оперативной памяти и пропускной
способности CPU/PCIe, поэтому реальное ускорение может быть немного меньше двух раз. Модели на
диске не дублируются: все воркеры используют общий portable-кэш `models/`.

В консоли печатаются номер запроса, GPU, найденная область лица, crop, seed, каждый
diffusion-шаг и итоговое время. `/health` показывает `gpu_count`, состояние `busy` каждой
карты, `active_jobs` и `queued_jobs`. API слушает только loopback.

Настройки очереди и GPU в `config.json`:

- `gpu_indices="auto"` использует все совместимые видимые GPU. Чтобы ограничить пул, укажите
  список, например `[0, 1]`. Разовый запуск только на одной карте: `start.bat -GpuIndex 1`.
- `max_queue_size=32` задаёт число ожидающих заданий сверх работающих. При заполнении API
  возвращает HTTP 429 вместо бесконтрольного расхода RAM.
- `max_batch_size=16` ограничивает число слайдов в одном пакетном запросе. При `seed=42`
  элементы получают seed 42, 43 и далее; при `seed=-1` каждому назначается случайный seed.

Полезная настройка качества:

- `crop_padding_ratio=1.0` оставляет вокруг маски запас в один её размер с каждой стороны.
  Уменьшите до `0.6–0.8`, если лицо в результате всё ещё слишком мелкое; увеличьте до
  `1.2–1.5`, если модели не хватает причёски и окружающего контекста.
- `default_ip_adapter_scale=0.8` задаёт силу сходства. Диапазон `0.7–1.0` обычно полезен:
  выше — больше сходство, ниже — больше свободы стилизации.
- `default_strength=0.9` сохраняет часть исходной структуры. Значения ближе к `1.0` сильнее
  перерисовывают лицо и чаще дают артефакты.

Для портретов реальных сотрудников используйте фотографии только с необходимым согласием.
DreamShaper распространяется по CreativeML OpenRAIL-M, IP-Adapter — Apache-2.0. Публичные
веса InsightFace разрешены только для некоммерческих исследований; эта конфигурация не
предназначена для коммерческого применения без отдельной лицензии InsightFace.
