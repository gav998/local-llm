# Digitizer

Digitizer размечает PDF прямоугольниками, распознаёт каждый прямоугольник через
локальный PaddleOCR и хранит весь результат в одном Markdown-файле рядом с PDF:

```text
document.pdf
document.pdf.digitizer.md
```

Исходный PDF не изменяется. JSON/JSONL-файлов документа, внутренних ID,
шаблонов, групп, материализованного результата и миграций старой схемы нет.

## Модель данных

Markdown является единственным источником данных. Один объект начинается с
маркера типа, каждая область — со следующего маркера, а её текст идёт сразу за
ним:

```md
<!-- digitizer:object {"type":"document_header"} -->
<!-- digitizer:region {"field":"organization","page":1,"rect":[0.12,0.08,0.44,0.06],"rotation":0,"status":"recognized"} -->
ООО «Пример»
<!-- digitizer:region {"field":"approval","page":1,"rect":[0.58,0.07,0.31,0.15],"rotation":0,"status":"recognized"} -->
Генеральный директор Иванов И. И.

<!-- digitizer:object {"type":"table"} -->
<!-- digitizer:table {"field":"body","page":3,"rect":[0.06,0.22,0.88,0.61],"rotation":0,"status":"recognized","grid":{"x":[0,0.5,1],"y":[0,0.5,1],"statuses":[["recognized","recognized"],["recognized","recognized"]]}} -->
| 1 | 2 |
| --- | --- |
| Изделие А | 12 |
| Изделие Б | 7 |
```

Порядок объектов и областей в файле является их порядком в приложении. Ссылок и
ID нет. Несколько блоков строк одной таблицы — это несколько `digitizer:table`
маркеров внутри одного объекта, в том числе на разных страницах.

`rect` содержит нормализованные координаты `[x, y, width, height]`. Для таблицы
`grid.x` и `grid.y` — строго возрастающие границы от `0` до `1`, а
`grid.statuses` хранит статус каждой независимо распознаваемой ячейки.
`grid.columnTypes` хранит выбранные пользователем типы столбцов, необходимые
для выгрузки связей марок ГСМ.

Поддерживаются статусы `pending`, `queued`, `running`, `recognized`, `modified`
и `error`. После нового запуска временные `queued`/`running` читаются как
`pending`. Текст ошибки присутствует только у области со статусом `error`.

## Типы и OCR

Предметная схема целиком находится в `config.yaml`. Корневой ключ только один —
`types`; первый тип используется первым в интерфейсе. У типа есть отображаемое
имя и словарь полей. Поле с `kind: grid` является таблицей, остальные поля —
обычными текстовыми областями. Каждому полю обязателен собственный `prompt` с
двумя сообщениями:

```yaml
prompt:
  instruction: >-
    Системная инструкция для модели.
  input: >-
    Значение выбранной области: {cell}
```

В `instruction` и `input` переменная `{cell}` всегда означает одно конкретное
значение, для которого нажата кнопка ИИ: обычную текстовую область либо ячейку
таблицы. Имена полей текущего объекта (`{organization}`, `{text}`, `{body}` и
т. п.) содержат объединённый текст всех областей соответствующего поля и нужны
как контекст. Имя типа объекта (`{table}`, `{frame}` и т. п.) содержит весь
текущий объект. Значения берутся из текущего Markdown; все комментарии
`<!-- ... -->` перед отправкой модели удаляются. Чтобы ответ заменял только
выбранную область, её текст в шаблоне следует передавать через `{cell}`.

Тип объекта и тип поля не влияют на OCR. Поток всегда одинаков:

```text
PDF → прямоугольник → PNG-фрагмент → PaddleOCR → Markdown
```

Табличный блок делится линиями сетки. Каждая ячейка отправляется в тот же OCR
отдельно, а переносы строк результата ячейки заменяются пробелами. Кнопка `OCR`
в ячейке повторно отправляет на распознавание только её собственный PNG-фрагмент,
не затрагивая остальные ячейки таблицы. Несколько
блоков строк можно добавить в один объект таблицы. Markdown хранит только текущее
значение ячейки без копии OCR в HTML-комментарии. После нормализации под списками
показывается фотография ячейки, которая каждый раз формируется из исходного PDF.
Старые комментарии `digitizer:ocr` удаляются при чтении и последующем сохранении sidecar.

Кнопка `✦ ИИ` формирует системное и пользовательское сообщения по шаблонам поля
и отправляет их в OpenAI-совместимый API. Для обычной области `{cell}` заменяется
текстом этой области, а ответ модели заменяет только её. У таблицы такая кнопка
находится в каждой ячейке; шаблон может передать модели всю таблицу как контекст
через `{table}`, а исправляемую ячейку — через `{cell}`. Ответ модели заменяет
только значение выбранной ячейки. Как и после OCR ячейки, переносы строк в нём
заменяются пробелами, а необходимые для Markdown-таблицы символы экранируются
при сборке строки.

Каждый запрос к chat completions и соответствующий ответ или ошибка дописываются
одной JSON-строкой в `logs/llm.log.jsonl`. Записи содержат UTC-время и уникальный
идентификатор запроса; файл не перезаписывается при новом запуске.

## Нормализация марок ГСМ

При запуске Digitizer получает два CSV-файла. Справочник допустимых значений
должен иметь заголовки (разделитель может быть `;`, `,` или табуляция):

```csv
Марка ГСМ;Нормативный документ;Применимо для наземной техники;Применимо для авиа техники;Применимо для морской техники;Порядок назначения и условия применения;Индекс НАТО
Т-1;ГОСТ 10227-86;+;+;-;По инструкции;F-34
Т-2;ГОСТ 10227-86;+;;-;;
```

Последние пять столбцов необязательны: старый справочник только с маркой и
нормативным документом остаётся корректным. В столбцах применимости допустимы
`+`, `-` и пустая ячейка.

Пути задаются один раз при запуске. Перед каждой нормализацией Digitizer
проверяет, не изменился ли справочник, и при изменении перечитывает его без
перезапуска приложения. CSV связей также перечитывается непосредственно перед
каждым дополнением, поэтому внесённые вручную примечания не теряются.

Кнопка `≋` у области нормализует весь её текст, а такая же кнопка в ячейке —
только выбранную ячейку. Результат хранится в Markdown в строгом виде:

```text
Т-1 по ГОСТ 10227-86; Т-2 по ГОСТ 10227-86
```

Каждая найденная пара показывается отдельной компактной карточкой. Зелёный фон
означает выбранное значение из `BrandsCsv`, жёлтый — неоднозначность или
отсутствующую связь, красный — полную пару, которой нет в справочнике. Внутри
карточки остаётся выпадающий список со всем справочником: сначала идут строки с
совпавшим нормативным документом или названием марки, затем остальные по
алфавиту. Шесть точек слева позволяют перетаскивать карточки, `×` удаляет одну
пару из ячейки, а двойной щелчок по значению включает ручное редактирование.

Под карточками находится поле `Введите, чтобы добавить`: Enter или кнопка `＋`
добавляют ещё одну марку с нормативным документом. В ручных полях подсвечиваются
латинские буквы, знаки, непарные скобки и повторные пробелы; подсветка не мешает
сохранить и повторно проверить введённый текст. Если полной пары нет в
`BrandsCsv`, на красной карточке появляется кнопка `＋ CSV`, которая атомарно
дописывает пару и сразу повторяет её нормализацию. Это работает и после ручного
редактирования карточки.

Нормализатор сначала делит строку по `;`. Если полученная подстрока делится по
` по ` на пару, которая уже находится в первых двух столбцах `BrandsCsv`, она
считается готовой, остаётся в ячейке ровно в пользовательском написании и дальше
не разбирается. Остальные подстроки делятся по
запятым, переводам строк и союзу `и`. Разделители внутри круглых скобок
игнорируются. Общие скобки и нормативный документ применяются ко всем
перечисленным маркам. Например,
`марка 1 и марка 2 (классов А и В) по ГОСТ 1234` даст два значения, каждое с общими скобками и НД.

Над столбцами каждого табличного блока находятся типы: другой, основная,
дублирующая, резервная, зарубежная, дублирующая/резервная одновременно, а также
три признака применимости — для наземной, авиационной и морской техники,
«Порядок назначения и условия применения» и «Индекс НАТО». Последние два
столбца содержат обычный текст и не проходят нормализацию марок ГСМ. В
ячейках признаков можно выбрать только `+`, `-` или пустое значение. OCR
автоматически приводит одиночные варианты плюса и минуса к этим двум знакам; для
совместимости ошибочно сохранённое старой версией значение `- по -` становится
`-`. Под выбором, как и в остальных ячейках, показывается исходное фото. Кнопка
`⇄ Связи` дополняет второй CSV строками следующего формата и не записывает дубликаты:

```csv
Первая марка;Тип связи;Вторая марка;Примечание
Т-1 по ГОСТ 10227-86;дублирующая;ТС-1 по ГОСТ 10227-86;
Т-1 по ГОСТ 10227-86;резервная;ТС-1 по ГОСТ 10227-86;
```

Эта же кнопка добавляет в `BrandsCsv` три столбца применимости, если их ещё нет,
а также «Порядок назначения и условия применения» и «Индекс НАТО». Значения
записываются в соответствующие поля основной марки той же строки блока. Если
основных марок в ячейке несколько, значения сохраняются для каждой пары марки
и нормативного документа. Пустые ячейки не стирают ранее записанные значения.
Повторная запись тех же значений не создаёт дубликатов; разные значения одного
поля для одной марки в одном блоке вызывают ошибку до записи CSV.

Как только тип выбран, все непустые ячейки столбца марок нормализуются
автоматически. Это же выполняется при открытии Markdown с уже сохранёнными типами.
Цвет ячейки показывает результат проверки: красный — марки нет в `BrandsCsv`, жёлтый —
марка есть, но нет нужной связи в `RelationsCsv`, зелёный — марка и связь найдены.

Столбец `Примечание` предназначен для ручного заполнения. Его значения
сохраняются при последующих дополнениях CSV.

Перед записью нужно выбрать тип каждого столбца, ровно один основной столбец и
минимум один связанный столбец, столбец применимости или один из двух текстовых
столбцов. Все непустые ячейки
марок участвующих столбцов должны быть нормализованы и однозначно выбраны из
справочника. Тип `другой` исключает столбец из построения связей.

## Интерфейс

Слева показан PDF. Проведите мышью по странице, затем в появившемся каскадном
контекстном меню выберите новый объект, его тип и поле либо существующий объект
и сразу нужное поле. Меню разворачивается в доступную сторону и остаётся в
границах окна. Новые области можно выделять, пока выполняется OCR или ИИ; их OCR
ставится в последовательную очередь и запускается автоматически. Рамки можно
переносить, растягивать за нижний правый маркер и поворачивать на 90°. После
изменения геометрии рамка получает статус `modified`; повторный OCR запускается
вручную.

Новый табличный блок имеет одну строку и один столбец. Сиреневая полоса над ним
добавляет столбцы, полоса слева — строки: щелчок создаёт разделитель в выбранном
месте. На полосе появляется точка, щелчок по ней удаляет разделитель; саму линию
можно перетаскивать прямо на PDF. Справа находятся объекты и редактируемый
Markdown. Все корректные изменения автоматически и атомарно записываются в
sidecar рядом с PDF. При незавершённом или некорректном ручном Markdown
автосохранение ждёт исправления, а сообщение об ошибке показывается в панели.

## Запуск

На целевой Windows 11 запустите `start.bat`, передав путь к справочнику марок и
путь к создаваемому/дополняемому CSV связей:

```bat
start.bat -BrandsCsv "D:\data\gsm.csv" -RelationsCsv "D:\data\gsm-relations.csv"
```

Оба параметра обязательны. Справочник должен существовать; CSV связей будет
создан, если его ещё нет. Portable Python и зависимости остаются внутри
каталога Digitizer; системный профиль и `PATH` не изменяются.
PaddleOCR и llama.cpp могут запускаться отдельно. По умолчанию используются:

```text
PaddleOCR: http://127.0.0.1:9399
OpenAI API: http://127.0.0.1:6381/v1
Digitizer:  http://127.0.0.1:9400 (этот компьютер)
```

Digitizer слушает порт 9400 на всех сетевых интерфейсах. На другом компьютере
той же сети откройте `http://IP-КОМПЬЮТЕРА-С-DIGITIZER:9400`. Если соединение не
устанавливается, во входящих правилах брандмауэра Windows должен быть разрешён
TCP-порт 9400 для частной сети; создание такого правила может потребовать права
администратора.

Поле пути и кнопка `Выбрать на сервере` относятся к компьютеру, где запущен
Digitizer. Для PDF, находящегося на компьютере с браузером, используйте кнопку
`Загрузить PDF`: файл будет скопирован в `digitizer\data\uploads`, а Markdown
будет храниться рядом с этой серверной копией. Приложение рассчитано на
доверенную локальную сеть и не имеет авторизации; не публикуйте порт 9400 в
интернет.

Старые `.digitizer.json` не читаются и автоматически не мигрируются.
